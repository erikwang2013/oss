# M4 运维与 IAM 实施计划（工作令）

> 设计文档 §M4：**范围** = heal/scrub · rebalance · 版本控制 · 生命周期 · 桶策略/IAM · 审计 · 集群面板；
> **验收** = ① 不停机扩容后数据按新拓扑重分布、读路径全程可用 ② 版本控制（PUT×3=3 版本 / list_object_versions / delete marker / 回滚）
> ③ 生命周期到期自动转换/删除（jobs 表可见进度）④ 策略拒绝 + 审计记录。
> 本计划另含：M3 顺延项（多 set、`/api/v1/cluster/*`、`/metrics`、NTP/epoch 收口、MPU 补全）+ 代码自标债务主攻（大对象流式）。

## 钉子（防蔓延）

- **不做**（归后续里程碑）：SSE/对象锁/STS → M5；事件总线/Kafka/S3 Select/桶复制 → M6；站点复制 → M7/M9；openraft → M9；
  存储分层/Access Point/作业引擎完整版 → M8（M4 只做 jobs 雏形）；ListObjects v1 → 不做（README 已记）。
- 条件请求收严（If-Match TOCTOU / `W/` 弱校验）：**无真实互操作诉求前不动**（ponytail 标记原意；README 已知边界维持）。
- AK 查询缓存：不加（撤销即时性优先，SQLite 便宜）。
- 发布/推送：只在用户明确口令时执行（本地四闸 = 验收；CI 手动口径）。

## 切片 2：大对象流式（债务主攻）

- [ ] EC 编码流式：按「data 片整行」（row = data×shard_size 输入 → data+parity 片输出）分块编，行缓冲常量内存；
      末行补零对齐（现语义不变）。inline（≤128 KiB）保持内存路径
- [ ] `put_object` 流式写分片（含 CRC 落盘校验），去掉 `max_put_bytes` 的**必要性**（保留为防护上限）
- [ ] 读路径流式：`ShardByShard` 解码 + Range 只读所需行（现为整份重建后切片）
- [ ] MPU complete 流式（现峰值 ≈2.5× 对象 → 常量内存）；`mpu.rs:455` 注释收口
- [ ] 测试：大对象（如 96 MiB=12×8MiB 边界）往返 cmp + 内存峰值实测（/usr/bin/time -v 或 proc 采样）+ 既有 EC 单测全绿（编码逐字节兼容：同输入新旧编码器输出一致——直接对拍）
- [ ] 收口注释：`put.rs:129`、`ec.rs:3`、`read.rs:87/142`、`store.rs:1178`

## 切片 3：版本控制（验收 ②）

- [ ] meta：`Version` 加 `is_latest: Option<bool>` / `is_delete_marker: Option<bool>`（Option + serde default = 前向兼容契约，见 meta.rs 头注）；`XlMeta.versions` 多版本读写（读路径已按 Vec）
- [ ] 桶 versioning 状态：`buckets` 表加列 `versioning TEXT NOT NULL DEFAULT 'Off'`；S3 ops：`PutBucketVersioning`/`GetBucketVersioning`
- [ ] 写路径：Enabled → 追加新 Version（**不** recycle 旧版本：`recycle_old` 在 versioning on 时转 skip）；Off/Suspended → 现状（单版本 + recycle）
- [ ] delete：Enabled → 追加 delete marker Version；Off → 现状
- [ ] `GET/HEAD/DeleteObject?versionId=` + `ListObjectVersions`（s3s op）+ `DeleteObjects` 带 versionId；删指定版本 = 移除该 Version + 目录进 trash
- [ ] `ListObjectsV2` 只见 latest 且非 delete marker；回滚 = 对旧 versionId 走 copy（M4 不做 RestoreObject）
- [ ] 集群：版本追加仍走 `write_meta` quorum（整份 meta 重写，天然复用）；镜像/回收 RPC 不变
- [ ] 测试：PUT×3=3 版本 / list_object_versions 正确 / delete marker 语义（GET=404 with marker, 删 marker 恢复）/ 删指定版本 / 回滚 copy / 集群 4 节点版本一致；e2e_s3.sh 加版本段
- [ ] 定稿：S3 语义边界（Suspended 行为、MPU 与版本）写入 README

## 切片 4：heal/scrub + epoch 收口

- [ ] `heal` 子命令：fsck 差集基础上**批量补建**——缺键 meta 补建（已有）+ 分片批量补：对缺/坏片对象从 quorum 读完整、重写本机槽；桶目录补建（`missing_bucket_dirs`）

## 执行模型

- 主会话 = 唯一写者（crates/web/docs 全归它，串行切片）；**团队 = 验证与记账**：`verifier`（每切片四闸 + 对抗核查）、
  `e2e-runner`（关键节点跑真进程 e2e）、`docs-fixer`（README/定稿段落，只碰 docs）。
- 每切片收口顺序：单测绿 → clippy/fmt 绿 → verifier 对抗核查 → 定稿 → 本地提交（不推送）。
- 内存纪律：同一时刻只跑一个重活（编译/e2e/镜像构建），背景见宿主 OOM 史（e2e 全文 18m34s 单次跑穿前有三次被杀记录）。
