## 切片 2：大对象流式（债务主攻）

**预研结论（钉子）**：写路径已把 body 磁盘暂存（`harvest_body` → `tmp/part.1`），内存峰值只在
「读回 part.1 → 整份 `ec::encode` → 12 片」一步（≈2.25× 对象）；MPU complete 峰值 ≈2.5×。
EC 按**列**独立（`ShardByShard` 逐列编码），任意按「data 的整数倍」切块流式编/解都成立。

**设计决定**：
- 块宽 `W = 64 KiB`（每片每块输出 W 字节）；输入块 = `data×W = 512 KiB` → 输出 12×64 KiB。
  末块输入补零到 `data×W`（全片定长 `shard_size = 块数×W`，格式不变——`shard_size` 本就在 meta 自描述）。
  **语义兼容而非逐字节兼容**：旧读端按 meta 的 `shard_size` 重建，新旧数据互读成立；对拍测试改按「旧写新读 + 新写旧读」。
- 远端分片：`ShardWrite` 加 `offset: u64`（0=建/截断）与 `chunk_crc32c`（**逐块**校验，保住「服务端先验后落」）；
  整片 CRC32C 由写端增量累计（`crc32c_append`）存 meta。`ShardRead` 加 `offset/length`（0,0=整片，向后兼容）。
- 读路径：整读 → 逐块解码攒进输出（峰值 2×→1×+O(块)）；**Range 只读命中块**（seek = 块号×W；本地 seek+read、
  远端 offset/length）。缺失块用 EC 重建后做**逐块对偶校验**（同一块号切片降维成 12×W 的 rs.verify）——
  Range 读不依赖整片 CRC（现格式没存逐块 CRC，不宜为它膨胀 meta）。
- 内联（≤128 KiB）与 `ec.enabled=false`（part.1 原样）路径不动。`max_put_bytes` 保留为防护上限（不再是必要约束）。
- 本轮**不做**整读的 HTTP 层流式（`get_object` 返回 `Bytes` 的 API 形态不动；改流式是后续独立项，收益只有峰值 2×→1×）。

- [x] `ec.rs`：逐块编/解辅助（定宽块、增量 CRC、末块补齐、逐块 verify）——**预研修正：不需要
      `ShardByShard`**，普通 `ReedSolomon::encode/reconstruct/verify` 按列独立，逐块喂 `12×W` 切片即可；
      另加**留一坏片定位**（单片损坏剔除+parity 重建自愈；≥2 片 fail-closed）
- [x] `put.rs`：`stage_payload`/`stage_payload_multi` 换分块编（12 个本地句柄追加写 / 远端逐块 `write_shard(offset, chunk_crc)`）

- [x] `mesh.rs` + `xl-proto` + `xl-client`：两个 RPC 的字段扩展与服务端切片读写（含 16 MiB 读长上限防呆）
- [x] MPU complete 流式（经 `stage_payload` 自动继承分块路径）；`mpu.rs:455` 注释收口
- [x] 测试：分块边界往返 cmp（`chunked_shards_interop_with_whole_path`：W 倍数 ±1/末块补零）；**旧写新读**专测（含 ss=75000 多块 + 跨片段区间第二例——**该扩展当场抓到旧布局抽取真 bug**：短末块补零尾巴覆盖相邻片段数据，已修）；新写旧读在编解码层证（分块产物可被整份 `reconstruct` 直读 + meta CRC=整片重算）；SHA 终验回归测试重建；**内存峰值实测 96 MiB 对象 VmHWM=110 MiB**（阈值 200 MiB，旧路径 ≈240+ 必超）

## 切片 5：rebalance / 不停机扩容（验收 ①；执行前先出子设计评审）

**子设计 v2（verifier 评审通过，A–J 已并入）**：

**核心机制**：`ShardRef.drive` 存写入时刻槽位 → 读路径按对象自解析——异构放置天然可读
（**前提 = 修 A**）。扩容 = 放置开关 + 追加式拓扑 + 逐对象搬迁。

- **A（架构必修）**：`ShardRead/ShardWrite/delete_shard` 全部**携带 slot**（来源恒为 meta 的
  ShardRef.drive / 搬迁前记录的老槽）；服务端校验改为「槽位属本机」+ 按槽拼路径；
  **删掉服务端的放置重算**（local_slot_of_shard 与 topo.slot_of 一并退役）。修后远端面
  与本地面同口径；搬迁删老片显式带 flip 前老槽。
- **B（放置开关）**：v2 用**显式开关**启用（cluster 配置 `placement = "v2"`；混版集群
  fail-closed 可诊断）；单机多盘无混版问题：`slot_count > shard_count` 时自动 v2。
  ≤12 槽恒等放置零 churn。
- **J（放置函数）**：`hash = sha256(bucket ‖ '/' ‖ key)` 前 8 字节（crc32c 线性可被
  恶意 key 定向聚集）→ `slot_i = (hash + i) % slot_count`（i∈0..12 两两互异 ✓）。
  新增配置校验：**每节点 drive_count ≤ parity**（保证单节点丢失 ≤4 片）。
- **C（搬迁提交）**：copy 在锁外；「重读 meta → 校验 uuid/epoch 未变 → write_meta」**全程
  持对象锁**——并发 put 与搬迁方不得同 epoch 竞争覆盖；链变则放弃该对象下轮重试。
- **D（残留治理）**：fsck 增「stray 分片文件」扫描——版本目录内 `part.*.*` 文件与 meta
  的 ShardRef（按槽属本机者）比对，多出的记 stray 并（--repair）删除；覆盖 copy 后
  flip 前崩（目标盘多文件）与 flip 后删老片崩（老盘多文件）两种残态。
- **E（搬迁范围）**：每键「链尾向前第一个非 marker 数据版本」；历史版本留老槽（自描述
  可读）；inline/旧 parts/未完成 MPU 不在范围；meta 重写保留整链、不动 is_latest、
  链尾 revision epoch+1（切片 4 不变量）。
- **F（EXDEV）**：跨盘 rename 必挂 EXDEV——**实现裁决：纯分块 copy（read_shard_block →
  write_shard_chunk），无 rename 路径 → EXDEV 不存在**；rename 同盘快路径未做（记档，
  数据量上来再加）。flip 提交点的耐久前提 = 目标片写完成（分块 is_final 路径 fsync 文件+
  目录；整片路径同 cfg.fsync）——两条路径都成立（verifier 注记 3 补）。
- **G（加盘位置）**：只支持**最后节点加盘**（中间节点加盘 → 其后 bases 位移 → 指纹
  拒启，既有校验兜住）；加节点尾部追加成立。文档写死。
- **H（指纹 v2）**：记录 `v2 node=X slot=Y`（去 slot_count）；读时兼容 v1（忽略 slots=，
  按 (node,slot) 校验）；node id 禁空白。
- **I（容错）**：逐对象 best-effort（quorum 不足/目标 down → 跳过入报告）；flip 前新副本
  已 fsync（分块 is_final 路径既有）；同刻只跑一个 rebalance（文档）。
- **残窗记档**：flip 后立即删老片 vs 在途旧 meta 读者 → 瞬缺片走 EC；极端重叠可能单次
  失败。不做延迟删除/不做 miss 回退双读。
- **缩容/回退**：不支持且**回退配置不可行**（槽 ≥ 新 count 的 shard → fail-closed 500），
  只能前滚——README 写明。
- **附加**：`rebalance` 逐对象「现槽位 vs 目标槽位」比对，本地 rename/跨节点分块 RPC；
  `--dry-run` 报告；幂等（已达标跳过）。

- [x] drives.rs：放置函数（sha256 前 8B **大端约定钉死** + 集群显式开关/单机槽超自动）+ 指纹 v2 兼容（parse_topo_record 忽略 v1 slots=）+ 校验（node id 禁空白 / drive_count ≤ parity / **槽位总数 ≤255**——u8 截断防呆）

## 切片 8：多 set

- **S-A 配置面**：`[[cluster.nodes]]` 增可选 `set`（默认 0）；同一物理节点可在多个 set 各出一条
