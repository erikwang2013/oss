v1.32.12026-11-07修复默认配置启动 · 清理
  • 启动修复：v1.32.0 的缺省 [server] 仍选择已删除的 SQLite 后端，未显式配置 control_backend = "objects" 的安装会在启动时 panic（object control backend not attached）。v1.32.1 让对象控制根无条件装配，缺省、显式 objects 与省略 [server] 都可用。
  • 旧配置拒绝：control_backend = "sqlite"（TOML 或 OSS_CONTROL_BACKEND）启动失败，并提示用归档 v1.31.0 二进制执行 control-migrate；未知值同样拒绝。
  • 清理：删除已无测试目标的 scripts/capture_control_goldens.sh，A8 goldens 冻结在 v1.31.0；移除 no-db 门禁的 pending 机制与过期注释，snapshot-joined 管理员登录改为硬断言。
  • 文档：修正归档 v1.31.0 二进制 sha256 为 64 位 fc2ea96fd0eb1777724da7b9ad07b4ad6520da7373bc9780099d8a211560b1ae（v1.32.0 部分页面误写为 63 位）。
  • 验证：strict no-db e2e 115 pass / 0 fail / 0 skip；workspace 测试、clippy -D warnings、fmt 全绿；cargo tree -i sqlx 与 libsqlite3-sys 无包。
  • 性能复核：release build（fsync on、SATA SSD）单写控制 p99 9.2ms、8 写线程中位 p99 12.7ms、吞吐约 1.4k 次/s，达到单盘 ≤20ms 预算；高负载机械盘出现 >20ms 尾延迟尖峰，故不宣称任意负载下达标。
  • 兼容性：无 API、Wire 或数据格式变更；从 v1.32.0 直接替换二进制。v1.32.0 缺省配置从未成功启动，因此无需数据修复；已完成割接的部署照常运行。
v1.32.02026-11-07移除 SQLite · 对象控制根
  • 唯一后端：对象控制根成为唯一控制面后端，根对象 control/state/root 的 CAS 是唯一提交点；节点与大值内容寻址存于 <data_dir>/.oss.sys/control/state/{node,blob}/，节点本地运行态在 <data_dir>/.oss.sys/local/，Raft 日志/元数据/快照在 <raft.db_path>.d/。
  • 删除 SQLite：移除 sqlx/SQLite、migrations/、control-migrate 与旧库读取路径；[cluster]/[stretch] 静态拓扑和 database_url 不再接受，Raft 部署只保留 [site]/[raft]。
  • 一次性割接：停全部节点，冷备 oss.db/raft.db/数据盘；从 GitHub Release v1.31.0 下载归档的 oss-server-v1.31.0-linux-x86_64（sha256 fc2ea96fd0eb1777724da7b9ad07b4ad6520da7373bc9780099d8a211560b1ae），每节点先 control-migrate --from <oss.db> --state-dir <data_dir> --raft-db <raft.db> --dry-run 再 --apply，校验报告后启动 v1.32 二进制。
  • 回滚边界：首次新写入前可恢复备份并启动旧/归档二进制；之后没有反向写入器，只能恢复备份并接受割接后的写入丢失。所有 Raft voter/witness 必须同版本一起割接，不支持滚动升级或新旧混跑。
  • 性能：控制写 p99 仍未达原预算（debug 单机约 0.64s；目标单盘 ≤20ms、多盘 ≤50ms），需在 release build 重测并记录偏差，不宣称达标。
  • 升级说明：完整步骤、备份校验、多盘处理与冒烟清单见 对象控制割接 runbook；归档二进制是唯一能读取旧 oss.db/raft.db 的割接工具。

状态：已发布；缺省配置启动问题由 v1.32.1 修复。

v1.31.02026-11-06对象控制存储后端
  • 对象控制存储（opt-in）：`[server].control_backend = "objects"` 时，控制面按表存为节点本地 COW B+tree，单根 CAS 作为唯一提交点；Root/RootMeta/分配器与内容寻址 blob 落 `.oss.sys`，盘级多数派 quorum（drives/2+1）与启动 flock 防止双写者。
  • 27 张控制表适配：IAM（用户/密钥/权限/账户/成员/账本）、桶/策略/生命周期/事件/复制规则、AP/OLAP/VPC、作业/任务、outbox、站点、审计、上传与秒传索引；读侧热视图按 root generation 切换，只重建脏域，请求内保持单一 generation。
  • Raft 与集群：对象后端使用文件日志/元数据/快照（<db_path>.d/）与元数据型 witness 状态机；按 entry 一次根 CAS，业务拒绝也推进 applied，快照安装单次 CAS 且崩溃矩阵覆盖前后。
  • 站点与本地状态：站点 LWW apply/ship/配对统一走缝，游标与死信落节点本地文件；账户用量热路径落本地缓存，复制账本由采样器校准；上传、instant index、事件/复制 outbox 均不再触碰占位 SQLite。
  • 迁移与验证：离线 control-migrate 先写节点再 CAS 根，保留逐字节校验、回滚窗口与空 runstate 兼容；A8 goldens 作为对象后端永久 oracle；standalone/cluster cutover e2e 分别 68/68、70/70。
  • 性能：bulk 建树后 10 万行快照导入 8.3s、导出 1.5s（此前导入超时）；修复元数据型提交让热视图 generation 落后、进而每次写全量重载 10 万行的问题。
  • 兼容性：SQLite 仍为默认后端，对象后端 opt-in；无 API、配置、Wire/OSSCTL 或数据格式变更；控制写性能预算在本机仍未达标（对象约 5× SQLite p99），SQLite 删除前需继续优化或记录偏差。
