API 文档

oss 的对外协议是标准 S3。用 aws-cli、rclone 或任意 S3 SDK 连接，下面是最小请求、认证方式与协议边界。

oss S3 API 协议边界 继续阅读

oss S3 API

oss 兼容 S3 的桶与对象操作，支持 SigV4、Multipart Upload / UploadPartCopy / ListMultipartUploads、partNumber、Range GET 与 HEAD Range、ListObjects v1、版本三态、完整生命周期、桶策略与匿名 Principal、对象锁与保留期、事件通知、Select、复制与访问点。直接使用 aws-cli、rclone 或任意 S3 SDK。

  • 服务端点：http://127.0.0.1:9000，路径风格访问。
  • 认证：访问密钥 AK/SK，SigV4 签名。
  • 完整命令与配置：oss README。
最小请求
aws --endpoint-url http://127.0.0.1:9000 s3api list-buckets
aws --endpoint-url http://127.0.0.1:9000 s3api head-object \
  --bucket photos --key cover.jpg

协议边界

  • partNumber 与 Range 同时出现 → 400 InvalidRequest；v1.15 起复制与 tier 摄入透传 part_sizes，MPU 分段边界保持可读。
  • GET 多区间 bytes=0-9,20-29 不返回 multipart/byteranges：未签入 Range 时剥离并返回 200 整对象；Range 计入 SigV4 SignedHeaders 时返回确定性 400 InvalidArgument。
  • 匿名 AP 策略 Principal:"*" 与桶策略匿名基线取交集，仅放行数据面对象操作；控制面与对象锁/保留期头一律 403。
  • 生命周期支持 AbortIncompleteMultipartUpload；STS 支持 AssumeRoleWithWebIdentity（默认关闭，需 OIDC 配置）；AP 跨账户已支持账户根 principal，VPC 端点真实 PrivateLink 身份仍为非目标。
  • Select 支持 CSV/JSON/Parquet 输入与 BZIP2/GZIP（BZIP2 仅 CSV/JSON；ScanRange 与压缩流互斥）。MPU 新 upload_id 可跨节点路由；存量裸 UUID 仍粘原节点。
  • Batch 支持同提交者协作抢占与跨账户清单（管理员）；OSSCTL2/3 快照分别携带 level-2/3 数据，旧读者明确拒绝。
  • v1.17：多租户账户 MVP（账户/成员/状态/桶数配额；账户写不参与 Raft）；AP 跨账户账户根 principal 与 aws:SourceVpce 来源证明。
  • v1.17：DP-0 数据面 wire 版本握手（混版 503 peer_incompatible）；M8 运行态 fencing；M7 未映射 REPLICA 对账（管理员 CLI/控制台，默认 dry-run）。
  • v1.17：tier 分块哈希与归档 Range 直读（默认关闭）；CMK 离线 scan/rewrap/delete/trash；REPLICA 头需 site token 认证。
  • v1.19：DP-1 数据面混版门控与降级头；能力级别 1..3/OSSCTL3（扩展区、Ext 容器，生产 registry 为空）；租户 schema/回填与 M8 运行态快照；maintenance 与 cluster-shrink plan 只读规划。缩容 apply、Raft 租户 API、M8 多节点与生产 Ext 命令未交付。
  • v1.20：mesh gRPC 入站 TLS 物料热轮换（新连接取新配置，旧连接保持旧物料）；账户/成员写走 7 个 level-3 Raft 命令（按 username 自然键，OSSCTL3 快照含账户行）；缩容 topology v4 与离线 apply/verify/commit/rollback（v4 只在 commit 写，作回退防线）；滚动 e2e 在同版本 3 节点与 v1.13.1 旧二进制上通过。
