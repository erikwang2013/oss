项目介绍

吞吞（oss）是一块自己养大的对象存储：Rust 2024 编写，S3 兼容，从单盘一直长到跨站点强一致。

它不是只把文件存进去的薄壳，而是把存储内核、纠删码、集群 mesh、多站点复制、控制面和安全能力放在同一套代码里。你可以只跑一个进程做本地备份，也可以配置 3 个 voter 和 witness，让控制面在站点故障时继续工作。

项目从单盘切片开始，依次完成可用性、分布式、运维与 IAM、安全、数据流、多站点、控制面，走到 sync 桶与 Raft 强一致。2026-10-23 的能力边界清零补齐了 S3 协议细节、全链路 TLS、控制面作业/清单/分层/访问点与滚动升级；2026-10-24 的 v1.15.0 完成 AP/账户、TLS/CMK、tier 流式与多站点复制等硬化收口，v1.16.0 又补上 WebIdentity、MPU 跨节点、OSSCTL2、Batch 抢占与 M8 leader 门控等 backlog，v1.17.0 继续推进账户 MVP、DP-0 数据面握手、M7 对账与 M8 运行态 fencing；2026-10-25 的 v1.18.0 精简 README 并更新英文 README 与站点，无功能变更；2026-10-26 的 v1.19.0 完成 Wave1 地基：DP-1 数据面混版门控、能力级别 1..3 与 OSSCTL3、租户与 M8 运行态快照、维护模式与缩容只读规划。每个阶段都有可运行的 e2e、验收记录和对应文档。

它适合想理解对象存储内部实现的人，也适合需要一套可自托管、可审计、能继续改的 S3 兼容服务的团队。代码是开放的，边界也写清楚了：能做什么，不能做什么，都在 README 和版本日志里。

一块对象存储，
该有的都有。

从单机盘到跨站点控制面，oss 把常用的 S3 能力做进同一条数据路径，不靠外部组件拼装。

S3 协议，现有工具直接连

aws-cli、rclone 与 S3 SDK 走标准 SigV4。大文件自动 multipart，支持 UploadPartCopy、ListMultipartUploads、partNumber、v1 列表与 HEAD Range；浏览器也能分块上传与断点续传。

v1 listMPUpartNumberRange
aws --endpoint-url http://127.0.0.1:9000 s3 ls
aws s3 cp ./backup.tar s3://backup/

EC 8+4，多盘也不怕掉一块

每盘一份命名空间镜像，分片按 quorum 写入。拔盘可读、可修，启动与周期任务负责清理残骸。

8 data4 parity

分布式 mesh

静态槽位拓扑、跨节点 quorum 读写、读修复、heal、scrub 与 rebalance，节点故障不靠重启恢复。

quorumslotshealscrub

安全与锁定

SSE-S3 / SSE-KMS、对象锁与保留期、匿名桶策略、STS 临时凭据、SK 加密存库，以及监听器/节点间/出站全链路 TLS；权限从管理员到桶主再到三档读写删。

数据会流动

事件通知接 Kafka（SASL/SSL），S3 Select 做查询，桶复制与多站点复制负责把版本送到另一端；读访问也会发 ObjectAccessed 事件。

多站点与强一致控制面

sync 桶 remote-first 写与删，stretch 2×6 数据面，3-voter Raft 控制面，witness、11 表快照、cutover 与 force recovery；控制面支持滚动升级窗口，数据面仍非滚动。图为多站点复制拓扑，强一致控制面在其上叠加 Raft 与 witness。

控制台与作业

访问点（含 -s3alias / DeleteObjects / SourceIp）、Object Lambda 与 Batch（WASM）、Inventory（Parquet/Hive）、分层（本地冷盘 / 远端 GC）与生命周期完整 Filter，以及一个能看见集群状态的 React 控制台。

五个 crate，一条单向依赖。

存储内核不依赖框架，S3 适配层只做协议翻译，服务端负责把控制台、S3 与节点间通信装进一个 axum Router。

  • xl-store：提交协议、xl.meta、EC、盘布局与锁。
  • xl-s3：s3s trait 实现、SigV4、SSE、对象锁与访问点路由。
  • xl-proto / xl-client：gRPC mesh 协议与节点间客户端。
  • oss-server：控制台 API、上传、作业引擎、Raft 与 S3 fallback。

两条命令，先跑起来。

Docker 是最快路径。想改代码、做单机调试，就用源码构建。两种方式都会自动创建数据目录与管理员。

  1. 准备环境Docker 与 Compose，或者 Rust 1.89 与 protoc。
  2. 启动服务Docker 默认映射 9000 与 8080，源码模式默认 9000。
  3. 登录控制台首次启动会生成管理员口令，登录后创建访问密钥。
  4. 连接 S3把 endpoint、AK、SK 填进 aws-cli 或 rclone。
docker-compose.yml
git clone https://github.com/erikwang2013/oss.git
cd oss
docker compose up -d --build

# 首次启动后读取管理员口令
cat docker/secrets/generated.env

# S3: http://127.0.0.1:9000
# 控制台: http://127.0.0.1:8080
source build
# 需要 Rust 1.89+ 与 protoc
git clone https://github.com/erikwang2013/oss.git
cd oss
cargo build --release -p oss-server

OSS_ADMIN_USER=admin \
OSS_ADMIN_PASSWORD='change-me-please' \
./target/release/oss-server serve

# 控制台
cd web && npm ci && npm run dev

用你熟悉的 S3 工具。

把 endpoint 指向 oss，剩下的交给 aws-cli。建桶、上传、列目录、删除，都是标准 S3 操作。

  • 大文件自动 multipart，支持 Range GET 与断点续传。
  • 版本控制、生命周期、桶策略与对象锁按桶开启。
  • sync 桶写入先到远端，远端不可达时返回 503，不静默降级。

aws-cli
export AWS_ACCESS_KEY_ID=...
